# desktop

## Purpose

Electrobun desktop composition root with a React/Vite renderer, persistent WebView, tray and bundled local CLI.

## Interface

`native/main.ts` owns window, tray, trusted renderer RPC and local engine lifecycle. `native/rpc.ts` declares the renderer bridge. `native/engine.ts` adapts NDJSON to the bundled binary. The renderer is a TanStack Start SPA: file routes live in `src/routes`, `src/router.tsx` exports `getRouter`, `src/shell.tsx` owns the window layout, and the build writes `dist/client` for `views://main`.

Single-route pages and their private helpers live directly in their file-route
modules. Keep shared feature components under `src/features/`, without a separate
`src/pages/` forwarding layer.

`src/routes/_local/route.tsx` is the pathless native-tools boundary. It disables
SSR for native route lifecycles, provides the desktop capability in `beforeLoad`
and invalidates the Jobs loader on engine-ready/job-finished events. These tools
need no account session; browser preview keeps its unavailable notice.

Jobs reads belong to its route loader; mutations invalidate that route. Keep
auxiliary root errors silent and retain successful lists during failed reloads.
Files keeps its directory, pagination and unsaved editor state in the component.
Its reads use `src/hooks/use-local-request.ts`: stable memoized parameters, an
explicit refresh key and stale-response protection. Callers own data, reset and
error handling. Callback changes do not restart requests, and ignoring stale
results does not cancel the underlying IPC call.

## Ownership

Own native directory authorization and local UX. Runtime implementations live exclusively in CLI and shared schemas in `@raypx/contracts/local`; never import CLI source. Account calls use remote client/auth packages. Logout actions use `@raypx/auth/hooks`; the renderer owns navigation and session display.

`src/features/auth/components/auth-form.tsx` adapts the shared `@raypx/auth/client` form
for Desktop account URLs, auth client and router search. Shared forms own fields,
translated feedback and submission state; the renderer owns navigation. Renderer
route tests live under `src/test/` and stay outside file-route discovery.

The account route reads its remote projection in a client-only loader; auth
mutations invalidate route data on success. Keep Better Auth session updates as
invalidation signals rather than a second account-query state machine.

## Constraints

- Start is used only for its SPA build. There is no server at runtime: no server functions, server routes or server-only loaders.
- The root shell is prerendered at build time without device preferences or native APIs. Keep it text-free; translated UI and providers start inside `ClientOnly`. Packaged views use hash history.
- `src/routeTree.gen.ts` is generated by the Start plugin during `dev`/`build`; commit it, never edit it, and do not regenerate it with `tsr`.
- Bundle the exact matching CLI version and start it through an absolute packaged path. Never use a global executable or PATH lookup.
- Closing hides the window while tray scheduling continues. Actual Quit closes engine stdin and waits for cancellation before native exit.
- Engine failures show retry state; account, theme and language remain usable.
- Keep a persistent WebView partition. macOS uses WebKit; Windows bundles CEF with web security enabled.
- Only bundled views and loopback development content receive native RPC. Renderer cannot register arbitrary directory grants; use native picker.
- Local file authorization does not sandbox external commands. Commands run with normal OS user permissions.
- Interactive terminals use xterm in renderer and Bun.Terminal in the separately compiled CLI. The Electrobun host keeps its pinned Bun version.
- Bun/Turbo own tasks. Hutch only prepares the pinned Electrobun SDK and packages native binaries.
- SDK code and generated declarations remain ignored. Native strict checking uses generated declarations without weakening source checks.
- Theme/language are device preferences, survive logout and use shared UI/i18n entrypoints. The host writes validated preferences atomically and restores them through the preload before React starts; packaged WebKit custom-scheme localStorage alone does not survive restart.
- Keep the independent Vitest configuration. Native GUI acceptance is a separate explicit platform gate.

## Verification

`bun run --cwd apps/desktop check`, `bun run --cwd apps/desktop test`, `bun run build:desktop`, then `bun run desktop:build`.

`bun run --cwd apps/desktop native:smoke` runs packaged assets, the renderer file/task/terminal bridge, CLI handshake, tray lifecycle and a full process restart for device preferences and local state. It uses `RAYPX_NATIVE_SMOKE=1` with the `shell` then `restore` phases. `write` then `read` with a synthetic HTTPS API verifies actual packaged-origin session persistence and logout. Never count loopback HTTP as production cookie verification. Tests use the isolated smoke identity, WebView partition and local profile.
