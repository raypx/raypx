# web

## Purpose

TanStack Start SSR application for optional remote project access and device preferences. This
application is an independent composition root and is never imported by another workspace.

## Interface

- `src/routes/` holds file routes and their page components;
  `src/routeTree.gen.ts` is generated by the Start plugin.
- Shared feature components live under `src/features/<feature>/components/`;
  keep reusable non-route modules outside `src/routes/`.
- Application-wide layout components live under `src/components/`.
- Unit tests live beside source; DOM suites use `*.component.test.ts(x)`.
  Route composition tests live beside `src/router.tsx`, outside route discovery.
  Shared setup/fixtures stay in `tests/`. Independent unit/component projects use
  `node` for pure cases and happy-dom, DOM matchers and motion setup for components.
- `src/router.tsx` exports `getRouter`. `src/routes/__root.tsx` owns the document,
  theme script, preference providers and production service-worker registration.
  Keep layout and feature dependencies out of it.
- `public/manifest.webmanifest` launches the installed Web app at `/projects`.
  `public/sw.js` passes through GET document navigations and supplies an embedded
  bilingual fallback on network failure. Keep API requests and assets outside the
  worker and leave Cache Storage empty.
- Route-group layouts (`route.tsx` inside a `(group)` directory, no URL segment) isolate
  first-load JavaScript: `src/routes/(app)/` renders
  `src/components/shell.tsx` (`@raypx/blocks/shell` with the account menu and pending count) for
  settings, task and approval pages; `src/routes/(auth)/` uses the public header and
  centered authentication panel.
  Import heavy client modules only from the layout or route that needs them.
- `src/routes/(legal)/` holds public legal pages under a lightweight document layout.
  `/privacy` is account-free and does not load the app shell or account queries.
  Keep privacy disclosures aligned with local storage, remote projections and opt-in
  diagnostics; English and Chinese copy live in the `legal` catalog namespace.
  The header shares `ThemeToggle` and `LanguageMenu` with the other public layouts.
  `src/components/legal-footer.tsx` provides the shared entry from landing and auth pages.
- Every `(app)` route declares `staticData.page` (title key from `PageTitle` in
  `src/router.tsx` and a Blocks page layout). The shell derives breadcrumbs and the
  page template from it; pages never add their own outer width or gutters.
- `src/router.tsx` creates one TanStack QueryClient per router (per request on the
  server), passes it as route context and connects SSR dehydration through `@tanstack/react-router-ssr-query`.
- `(app)/route.tsx` resolves account context with `queryClient.fetchQuery(accountQuery())`
  while keeping the application shell public. Guests can browse projects, tasks, approvals
  and preferences; `SessionBoundary` mounts private views only after a confirmed session.
  `src/routes/(landing)/` owns the public `/` homepage with its own header and document
  layout, without account loaders or the workspace shell; its views live under
  `features/landing/components/`. A client-only `UserButton` shares the sidebar account
  menu with a fixed-size SSR placeholder and stays when the session check fails; sidebar
  session errors stay on the retry control. Landing views subscribe to Better Auth's
  shared session store after hydration: confirmed sessions open projects first and
  connect computers through settings; guests open projects and sessions from the hero,
  and sign-in return paths stay on the computer action. Pending checks show a disabled
  loading action, a failed check keeps the connect or sign-in action, and until the
  session is confirmed home keeps the public project and session actions. Home links
  projects, approvals, automations and memory and never mounts private project, device,
  task, job or memory reads; the account menu reads permissions only for confirmed
  sessions.
  Home stacks a centered hero with contextual draft help, a workflow preview with
  integrated step tabs, a three-step overview, workspace links with labelled example
  interfaces and a Desktop-to-Web connection band. The wider header links to the lower
  sections. The Base UI tabs select a labelled static-data example without mounting
  execution clients or private reads. `useDemoPlayback` plays its steps until a visitor
  chooses one or turns the labelled autoplay toggle off. Hover and step-tab focus hold it, and
  reduced motion starts it off. Pointer and autoplay changes use a short directional
  transition; keyboard and reduced-motion changes are immediate. Step tabs and workspace
  links use their titles as accessible names and their hints as descriptions; the
  diagram never implies a live connection or reads device state. The hero's particle
  trails and frame light share one eight-second loop. They and the decorative connection
  packets pause offscreen and in hidden tabs. Reduced motion leaves a static trail.
  The landing layout applies the `--brand-*`
  palette and clips horizontal overflow (`overflow-x-clip`, which keeps the sticky
  header).
  The `(app)/projects` route owns `/projects`, including its guest sign-in gate and
  remote project list. An unavailable API renders retryable feedback rather than a
  signed-out state. Account state is rechecked on navigation; sign-out handlers call
  `queryClient.clear()` before `router.invalidate()`.
- `src/preferences.ts` reads theme/locale cookies and the full weighted Accept-Language list on the server.
  The root passes this request snapshot to the language provider so SSR and the first
  client render use the same locale and catalog; browser storage is restored only
  after hydration. Language switches use `useLanguagePreference`, never a second
  locale state or route navigation.
  Authentication pages expose `ThemeToggle` and `LanguageMenu` in their top-right header;
  language changes preserve form drafts and the current return destination.
  Public headers use `LanguageMenu` and `ThemeToggle` from
  `@raypx/blocks/preference-controls` with the existing preference providers.
  Landing, authentication and legal layouts compose `PublicHeader` and `PublicBackdrop`
  from `src/components/public-chrome.tsx`; shared artwork and the pointer spotlight
  live in `src/components/artwork.tsx`, and the logo palette (`--brand-*`) in
  `src/components/brand-accent.ts`.
  Theme clicks cycle light → dark → system → light; the icon and accessible label
  reflect the current preference, and the tooltip shows the next one.
- `src/features/auth/client.ts` creates the Better Auth client; `src/features/tasks/client.ts`
  creates the oRPC relay task client so sign-in pages never load relay schemas.
  `src/features/auth/account.ts` adapts `@raypx/account` reads to SSR cookies and
  browser credentials. Shared account views come from `@raypx/account/client`.
- Authentication forms use `AuthForm` from `@raypx/auth/client`, backed by
  `@raypx/auth/hooks`.
  Sign-out uses the hook directly; routes own navigation and loader invalidation.
- `features/settings` composes `ProfileSettings` and `AccountSessions` in a lazy
  dialog mounted by the shared `UserButton` on landing, workspace and administrator
  layouts. `#settings/account` (also preferences, diagnostics, password, sessions and
  instances) owns opening and category selection without replacing the background
  route, search or mounted drafts. Opening pushes one history entry; switching replaces
  it. Close/Escape returns to that background entry; direct links simply clear the hash.
  Browser back/forward and reload restore URL selection. Unknown hashes open nothing.
  Private categories require a confirmed session and live `account.manage` permission;
  account reads are identity-keyed, and identity changes discard dialog drafts. Category
  panels mount on first visit and retain drafts while switching. Local settings search matches category labels and
  bilingual setting keywords without mounting private reads; choosing a result opens
  its category. Enter opens the first result, Escape clears a query before closing,
  and clearing search preserves drafts. Cmd/Ctrl+K focuses search; arrows and Home/End
  move through results without opening them. Nested menus own their Escape handling.
  Closing discards unsaved inputs directly. Narrow screens use a category Select. The
  dialog keeps the category icon and account/device scope visible above its scrolling
  content. Profile edits, sessions, registration states and diagnostics use shared
  icon and badge primitives; registration never implies a computer is online.
  The password category loads the signed-in account's linked login methods.
  Accounts with a password open Auth's change dialog; others request an email
  setup link. Dismissal clears credential drafts and preserves the parent settings
  dialog; password changes and their account refresh prevent dismissal while pending.
  The `/projects` page lists authorized remote projects grouped by computer.
  Project/session selection lives in validated URL search. The composer consumes
  that target and never executes on navigation or guest draft restoration. The
  shell opens the composer with `/tasks?compose=true`; the route clears the flag
  after focusing the editor.
  Account views in `features/auth/components` call the existing Better Auth client methods.
  Name saves invalidate the account query before reloading route context. Session
  lists stay in component memory, never query caches or persisted storage; tokens
  are used only for revocation and never rendered. Remount them on account changes.
  Confirm session revocation with the shared shadcn dialog and keep failures retryable.
- `src/routes/(auth)/` holds the authentication routes under the public logo,
  theme and language header. A single bordered 16px panel caps at 60rem; at 1024px
  it pairs the form with numbered product facts and a labelled example approval in a
  5:4 split. The layout applies the `--brand-*` palette and renders without entrances.
  Narrower pages use one column, a 25rem form and natural document scrolling. The
  application owns panel gutters; shared Auth owns fields and feedback. When signup
  cannot show the form, its unavailable and closed states keep an `h1`, a centered
  status and a full-width action like the form's completion states.
  Each route renders the thin `src/features/auth/components/auth-form.tsx` adapter
  with its mode. The adapter injects the client, router query and navigation into
  the shared form. The auth layout validates an application-page `returnTo` allowlist;
  login, signup and email callbacks preserve it. Login restores editing state, never
  an execution or approval intent. `/admin/settings` still redirects guests to login.
  Configured Google/GitHub OAuth returns through login to refresh the account and
  restore visitor drafts; failed authorization retains the destination and safe feedback.
  Sign-in without a return destination opens `/projects`; an explicit allowed
  destination is preserved. Public URLs stay flat, and changing routes remounts the
  form so inputs and request feedback reset.
- `/health` is a server route for process liveness; it never calls the API.
- `/automations` composes `@raypx/jobs/client` with API adapters. Guests see a
  contextual sign-in gate with return navigation; only a confirmed account mounts
  schedule, device and history reads. Keep private state in account/client-keyed
  component memory and cancel old requests on either change. Run-history links
  open a validated `/tasks?taskId=...` projection, including tasks outside the
  current list page; navigation never creates or resumes execution.
- `vite.app.config.ts` adds security headers to every Nitro response:
  framing, plugin, base and form-target CSP directives, HSTS, nosniff, Referrer and
  Permissions policies. Inline hydration and theme scripts mean script-src needs nonces
  before it can be restricted.

## Ownership

Web owns route composition, navigation and account loading. Shared DOM auth forms
belong to auth's client entry; primitives and theme belong to UI. Translations and language
preference adapters belong to i18n. Authentication is provided by auth and remote
behavior by client/contracts.

## Constraints

- Remote behavior goes through the API over HTTP. Never import API, auth server,
  DB or mail code, and do not duplicate API behavior in server functions.
- Server rendering forwards only Better Auth cookies to the API, never other inbound
  headers. Without a session cookie it returns signed-out context without an account RPC.
- Guest task editor handoff uses bounded, expiring sessionStorage scoped to the API
  origin, browser tab and (after login) account. URLs carry only a nonce. Keep failed
  login/storage attempts recoverable and never send a restored draft automatically.
- Render-time code must not touch `window`/`document`; read the URL through the router.
- `VITE_API_URL` is baked at build time for browser and server. The server must
  receive the session cookie: one shared origin, or API AUTH_DOMAIN on sibling hosts.
- Verification and password reset links finish in Web.
- Theme and language persist on this device as storage plus cookies, independently
  of account sessions, so the first server render already matches them.
- Translate safe error codes. Never display arbitrary server diagnostic messages.
- Dev, build, preview and production run under Bun (`bun --bun vp`); the Nitro `bun`
  preset traces Bun export conditions, so start the output with `bun`.
  Common target options come from `@raypx/tooling/build/nitro`; Web owns its Start plugins and React tracing.
- `apps/web/Dockerfile` is shared by Compose and Railway. Keep build commands there;
  `deploy/build.sh` adds Compose-only cache mounts to a temporary copy.
- Do not edit `src/routeTree.gen.ts` or regenerate it with `tsr`.
- Keep independent test configuration so application plugins stay outside tests.

See [foundation architecture](../../docs/architecture/0034-extensible-foundation.md)
and [verification](../../docs/development/testing.md).

## Verification

```sh
bun run --cwd apps/web check
bun run --cwd apps/web test
bun run --cwd apps/web e2e -- settings.spec.ts
bun run build:web
```

Web browser cases live in `e2e/` and use `@raypx/e2e/testing`; shared flows register
through `@raypx/e2e/journeys/*`. The `web` Playwright project builds only Web through
cached `build:e2e` and starts the real compiled SSR server. E2E uses a separate Bun
tsconfig, checked by `check`; browser runs do not repeat type checking. Root
`test e2e --package web` uses the same plan; `-- --list` needs no build or server.

## Remote tasks

`/memory` composes `@raypx/memory/client` through browser API adapters. Mount
account documents and project reads only after SessionBoundary confirms login.
The task composer and cloud schedules receive the same account library as an
explicit React prop. Guest draft handoff never carries private source references.
Task details show the immutable creation snapshot without reading current documents.

Task and approval routes and sidebar session groups use `@raypx/tasks/client`.
The shell imports the inbox badge from `@raypx/tasks/client/pending-count`.
Remote reads use account-keyed state and visibility-aware relay subscriptions.
Settings lists device connections. Never render agent content as HTML or send a
raw local method, path or executable to the API.

## Development diagnostics

The development-only `@raypx/devtools` bridge is lazily mounted inside the existing
Router/Query and preference providers after hydration. `vite.app.config.ts` enables
the official Vite DevTools only for serve. Keep production imports eliminated;
never expose query hashes/data, URL values or loader results in diagnostic snapshots.
The shared panel owns metadata display and browser/manual clipboard handling.

## Browser analytics

`features/analytics` injects public build config and a device-local preference store
into `@raypx/analytics`. Keep the SDK deferred and auth/account dependencies outside
the document root. Route catches and React/global errors pass only sanitized app
frames. Statistics and errors default off independently; identify internal IDs only
with statistics consent, reset on logout and never capture raw task parameters.
Source-map upload is an explicit release step; ship those same injected assets.

## Administrator configuration

`/admin/settings` and `features/config/` provide the Web-only configuration
center with Site, Object storage and Email tabs. `features/auth/access.ts` declares each Web page's
permission. Account-scoped `account.access` reads filter sidebar entries and gate
private page mounts through `PermissionBoundary`, including direct navigation.
Loading, failed reads and identity changes never reuse another account's grants.
Guests retain public pages and contextual sign-in gates; Desktop local tools require first-time instance enrollment and then stay available offline. API permissions remain authoritative on every request and save.
Keep editable drafts through network failures and revision conflicts, with explicit
reload/discard actions. Object storage and Resend credentials are write-only, stay in the
form until save or discard, and are absent from responses. Public settings supply
the shell label and signup availability.
The configuration tabs animate the selection indicator for pointer input. Keyboard
selection and reduced-motion preferences disable that transition. The three forms
share their save, discard and confirmation layout.

## Account access and administration

`features/auth/access.ts` owns the page policy for navigation and `beforeLoad`
guards. Private routes use `webPageGuard` and `PageAccessFeedback`; public guest
workspaces remain available. Permission reads use the isomorphic account-access
adapter with filtered SSR cookies. Keep live PermissionBoundary checks for revocation.
Auth's group redirects confirmed accounts from login/signup while preserving callback,
recovery and browser-only draft completion. A successful login navigates after cache
clear, without invalidating the auth route mid-completion.
`/admin/users` composes the account-keyed users feature through Better Auth's existing
Admin client. Its shared DataTable renders server searches, registration-date sorting,
and 20-row pagination. Changing sort returns to page one. Role changes require
confirmation, prevent self-editing, and retry a completed mutation's refresh separately.
The role preview and change dialog derive their permission lists from Auth's shared ACL.

## Administration console

`src/routes/(admin)` owns `/admin`, `/admin/users`, `/admin/settings` and `/admin/audit`
under the independent AdminShell. The group resolves fresh account and admin.read
before loading; feature guards and live boundaries remain authoritative for mounting.
Never mount task clients, remote project navigation or pending counts in this shell.
Public configuration reads stay in their existing lightweight module. Account menus
link to one console entry and preserve account-dialog return history.
`features/admin` owns account/origin-keyed overview, dependency and audit
queries. Statistics distinguish failed reads from zeroes and use explicit UTC dates.
Audit searches are bounded by date range and use server cursor pagination; there are
no edit/delete/export actions. Unknown outcomes remain unknown until the server
confirms them. Clear private administration state across identity changes.

## Catalog composition

Own dash, users, site, guest and legal in private `locales/<language>/` files.
Explicitly compose the nine shared package language entries with these namespaces.
Infer app translation types from the English entry; shared views read the same
messages context through their private typed hooks.
The app-owned static/lazy entries are selected by the i18n Vite plugin for this
client only: English static, Chinese lazy, SSR static. Preload before hydration.
