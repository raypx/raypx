# web

## Purpose

TanStack Start SSR application for account access and device preferences. This
application is an independent composition root and is never imported by another workspace.

## Interface

- `src/routes/` holds file routes and their page components;
  `src/routeTree.gen.ts` is generated by the Start plugin.
- Shared feature components live under `src/features/<feature>/components/`;
  keep reusable non-route modules outside `src/routes/`.
- Application-wide layout components live under `src/components/`.
- Tests live under `tests/`, alongside shared test setup; keep test files
  outside `src/routes/` so route discovery needs no test-specific exclusions.
  Use `tests/unit/` and `tests/component/` for test kind, then feature directories.
- `src/router.tsx` exports `getRouter`. `src/routes/__root.tsx` renders only the document,
  theme script and preference providers; keep layout and feature dependencies out of it.
- Route-group layouts (`route.tsx` inside a `(group)` directory, no URL segment) isolate
  first-load JavaScript: `src/routes/(app)/` renders
  `src/components/shell.tsx` (`@raypx/blocks/shell` with the account menu and pending count) for the account,
  settings, task and approval pages; `src/routes/(auth)/` is a logo-only layout for sign-in pages.
  Import heavy client modules only from the layout or route that needs them.
- `src/router.tsx` creates one TanStack QueryClient per router (per request on the
  server), passes it as route context and connects SSR dehydration through `@tanstack/react-router-ssr-query`.
- `(app)/route.tsx` resolves account context with `queryClient.fetchQuery(accountQuery())`
  while keeping the application shell public. Guests can browse home, tasks, approvals
  and preferences; `SessionBoundary` mounts private views only after a confirmed session.
  An unavailable API renders retryable feedback rather than a signed-out state. Only a
  signed-in result stays fresh; sign-out handlers call `queryClient.clear()` before
  `router.invalidate()`. The account page reads the result from route context.
- `src/preferences.ts` reads theme/locale cookies and the full weighted Accept-Language list on the server.
  The root passes this request snapshot to the language provider so SSR and the first
  client render use the same locale and catalog; browser storage is restored only
  after hydration. Language switches use `useLanguagePreference`, never a second
  locale state or route navigation.
- `src/features/auth/client.ts` creates the Better Auth client; `src/features/tasks/client.ts`
  creates the oRPC relay task client so sign-in pages never load relay schemas.
  `src/features/auth/account.ts` adapts `@raypx/account` reads to SSR cookies and
  browser credentials. Shared account views come from `@raypx/account/client`.
- Authentication forms use `AuthForm` from `@raypx/auth/client`, backed by
  `@raypx/auth/hooks`.
  Sign-out uses the hook directly; routes own navigation and loader invalidation.
- The account page composes `ProfileSettings` and `AccountSessions` from
  `features/auth/components`. They call the existing Better Auth client methods.
  Name saves invalidate the account query before reloading route context. Session
  lists stay in component memory, never query caches or persisted storage; tokens
  are used only for revocation and never rendered. Remount them on account changes.
  Confirm session revocation with the shared shadcn dialog and keep failures retryable.
- `src/routes/(auth)/` holds the authentication routes under the logo-only layout.
  Each route renders the thin `src/features/auth/components/auth-form.tsx` adapter
  with its mode. The adapter injects the client, router query and navigation into
  the shared form. The auth layout validates an application-page `returnTo` allowlist;
  login, signup and email callbacks preserve it. Login restores editing state, never
  an execution or approval intent. `/admin/settings` still redirects guests to login.
  Public URLs stay flat, and changing routes remounts the form so inputs and
  request feedback reset.
- `/health` is a server route for process liveness; it never calls the API.
- `/automations` composes `@raypx/jobs/client` with API adapters. Guests see a
  contextual sign-in gate with return navigation; only a confirmed account mounts
  schedule, device and history reads. Keep private state in account/client-keyed
  component memory and cancel old requests on either change. Run-history links
  open a validated `/tasks?taskId=...` projection, including tasks outside the
  current list page; navigation never creates or resumes execution.
- `vite.app.config.ts` adds security headers to every Nitro response (Node and Workers):
  framing, plugin, base and form-target CSP directives, HSTS, nosniff, Referrer and
  Permissions policies. Inline hydration and theme scripts mean script-src needs nonces
  before it can be restricted.

## Ownership

Web owns route composition, navigation and account loading. Shared DOM auth forms
belong to auth's client entry; primitives and theme belong to UI. Translations and language
preference adapters belong to i18n. Authentication is provided by auth and remote
behavior by client/contracts.

## Constraints

- Remote behavior goes through the API over HTTP. Never import API, auth server,
  DB or mail code, and do not duplicate API behavior in server functions.
- Server rendering forwards only Better Auth cookies to the API, never other inbound
  headers. Without a session cookie it returns signed-out context without an account RPC.
- Guest task editor handoff uses bounded, expiring sessionStorage scoped to the API
  origin, browser tab and (after login) account. URLs carry only a nonce. Keep failed
  login/storage attempts recoverable and never send a restored draft automatically.
- Render-time code must not touch `window`/`document`; read the URL through the router.
- `VITE_API_URL` is baked at build time for browser and server. The server must
  receive the session cookie: one shared origin, or API AUTH_DOMAIN on sibling hosts.
- Verification and password reset links finish in Web.
- Theme and language persist on this device as storage plus cookies, independently
  of account sessions, so the first server render already matches them.
- Translate safe error codes. Never display arbitrary server diagnostic messages.
- Dev, build, preview and production run under Node (`bun vp`, never `bun --bun vp`);
  the default production target uses Node 24.15.0. The node-server output traces Node export conditions.
  `build:cloudflare` uses Vite's cloudflare mode and Nitro cloudflare_module, bundles
  server dependencies and writes `.output-cloudflare`. Keep the default Node output separate.
  Common target options come from `@raypx/tooling/build/nitro`; Web owns its Start plugins and React tracing.
  Wrangler keeps page routes Worker-first so account pages remain request-rendered.
  `/assets/*` and `/favicon.png` use asset-first routing to avoid Worker invocations for static files.
  Its public-fetch flag lets SSR call the public API even when it is another Worker in the same zone.
- Do not edit `src/routeTree.gen.ts` or regenerate it with `tsr`.
- Keep independent test configuration so application plugins stay outside tests.

See [foundation architecture](../../docs/architecture/0034-extensible-foundation.md)
and [verification](../../docs/development/testing.md).

## Verification

```sh
bun run --cwd apps/web check
bun run --cwd apps/web test
bun run build:web
bun run build:web:cloudflare
```

## Remote tasks

`/memory` composes `@raypx/memory/client` through browser API adapters. Mount
account documents and project reads only after SessionBoundary confirms login.
The task composer and cloud schedules receive the same account library as an
explicit React prop. Guest draft handoff never carries private source references.
Task details show the immutable creation snapshot without reading current documents.

Task and approval routes use `@raypx/tasks/client`; the shell imports only
`@raypx/tasks/client/pending-count`. Both use account-keyed state and
visibility-aware relay subscriptions. Settings lists device connections. Never render agent
content as HTML or send a raw local method, path or executable to the API.

## Browser analytics

`features/analytics` injects public build config and a device-local preference store
into `@raypx/analytics`. Keep the SDK deferred and auth/account dependencies outside
the document root. Route catches and React/global errors pass only sanitized app
frames. Statistics and errors default off independently; identify internal IDs only
with statistics consent, reset on logout and never capture raw task parameters.
Source-map upload is an explicit release step; ship those same injected assets.

## Administrator configuration

`/admin/settings` and `features/configuration/` provide the Web-only administrator
page through the public API SDK. The sidebar link depends on the server access
check; API permissions remain authoritative on direct navigation and every save.
Keep editable drafts through network failures and revision conflicts, with explicit
reload/discard actions. No configuration secrets or deployment credentials enter
the browser. Public settings supply the shell label and signup availability.
