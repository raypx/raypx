# @raypx/skills

`/server` owns text-only reusable know-how and bounded, non-executing package
imports. `/server/postgres` persists account-owned availability and separate
Space-local Agent-created skills. Account skills never become another member's
resources. Agent enablement is per member and Agent, with fresh availability on
load. Run-start catalog text is checkpointed by Agents; a loaded body remains
untrusted reference material. Saves are fenced, Run/tool-call deduplicated change
tools under the ordinary approval/effect pipeline. No scripts, hooks, binaries or
local command servers are installed or run. New archive formats require explicit
validation rather than compatibility fallback.

Unit suites use injected repository ports. `test:postgres` needs an isolated
`*_test` database; each case removes its own Spaces and accounts.

`/model` owns skill forms, import reports and injected account CRUD/import ports.
`/client` renders account Skills settings in Web and Desktop; application adapters
supply the active Space and membership list. Availability controls appear only
with multiple Spaces. Imports send bounded Markdown/ZIP bytes for backend parsing;
never execute package content. Agent-created skills are labelled Space-local.
English and Chinese copy live in `/messages/en` and `/messages/zh`.
`test:unit` and `test:component` select pure and happy-dom suites separately.
